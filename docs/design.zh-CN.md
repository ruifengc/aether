## 执行中的任务可以接收新信息

Agent 的任务可能持续很久。工具需要时间，用户会补充要求，其他服务也可能返回新的结果。Aether 将这些输入作为消息，交给同一次运行继续处理。

应用提交消息后获得回执，可以继续做其他事情、补充信息、查询状态或订阅事件。等待任务结束是独立的操作。

会话保存多次任务之间的历史。一次运行是以成功、失败或取消结束的一段工作。同一会话最多有一次活跃运行；提交到该会话的消息会加入活跃运行，或在上次结束后启动下一次运行。

## 状态按顺序更新，耗时操作并发执行

每次运行有一个队列，按顺序处理新消息和返回的结果。模型读取当前状态的副本，提出输出、工具调用或等待决定。网络请求、工具执行和摘要在队列外进行，因此耗时操作不会阻止接收新输入。

```text
应用消息 ─────┐
外部通知 ─────┼─> 队列 ─> 状态 ─> 模型请求
工具返回结果 ─┘            ↑          |
                           |      检查模型决定
                           |          |
                           └── 工具 / 输出 / 等待 / 结束

应用 <── 查询 / 订阅 / 完成通知
```

模型结果返回时，内核检查它依据的输入版本。若已有更新的消息被接收，旧决定会在发布输出或启动工具前被丢弃，随后使用新状态重新请求模型。这项检查始终启用。

不同会话和多个工具可以并发执行。同一次运行中，模型请求、压缩或重试等待最多同时进行一项，不会并行推进多次模型决定。

## 模型提出下一步，内核负责执行

`Model.decide(snapshot, tools)` 返回一个 `Decision`。模型不直接执行已注册的工具函数。内核检查决定和执行额度后启动工具，工具结果以消息返回，包括错误和超时。

默认等待本批新工具全部返回。模型也可以选择下一步需要哪些结果，其余工具继续执行。等待选定结果时，用户消息仍会被接收。不等待任何结果也不会触发无输入的推理空转：需要另一条消息或工具结果到达，才会继续判断。

输出和结束分别处理。工具仍在运行时，可以先发布有用的中间回答。应用应根据最终状态判断任务是否成功，不能仅凭一次输出事件判断完成。

## 长时间运行有明确的限制

每次运行分别限制模型决定、工具、摘要和错误恢复次数。剩余额度会传给模型，也由代码在执行决定前检查，模型不能通过再次请求扩展额度。

历史超过输入估计上限时，Aether 对较旧的一段历史生成摘要，保留近期消息，并在空间允许时保留完整的旧用户消息。全部摘要片段成功后才替换原历史；压缩期间收到的新消息会保留。同次运行的恢复可以复用已经成功的片段，避免重复请求模型。

模型故障可以在原有限制内重试。工具故障作为结果交给模型处理；有外部影响的工具不会被自动重复执行。模型响应被截断时，不会发布残缺文本或执行不完整的工具参数。

## 职责分工

| 部分 | 职责 |
| --- | --- |
| `contracts.py` | 公共数据类型、工具定义和模型接口 |
| `runtime.py` | 接收消息、按序更新状态、执行工具、检查额度和发布事件 |
| `context.py` | 会话历史、输入估计和压缩 |
| `adapters/openai.py` | OpenAI 兼容请求、连接复用、响应解析和摘要 |
| `tools.py` | 可选的终端、文件和检索函数 |
| 应用 | 凭据、模型选择、任务指令、工具注册和结果展示 |

运行内核不依赖供应商 SDK 或终端应用。传给模型的工具定义只包含名称、说明和参数，不包含供应商专用包装或可执行函数；由适配器转换成具体供应商要求的格式。

Agent 管理传入的模型实例。关闭时先停止在途工作，再调用模型可选的 `aclose()` 方法。内置适配器自行创建和复用 HTTP 客户端，应用无需管理该连接。每个 Agent 使用独立的模型实例，配置可以复用。

## 当前边界

状态和消息去重记录保存在单个进程中，没有重启恢复、跨进程交付或持久任务队列。应用通过 `prune` 和 `forget` 明确释放已结束的记录。

摘要有损。输入限制使用 UTF-8 字节估计，而不是供应商的精确 token 数。取消不能撤销外部操作，也无法强制停止已经在线程中运行的 Python 函数。这些行为由接口和代码明确规定。
