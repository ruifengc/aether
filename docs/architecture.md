# Aether 架构与职责

目标是简洁、可参与、可观察的异步 LLM loop。四类基础操作是异步提交、内部流转、查询与注册通知；wait 是提交之后等待终态的便利方法。应用无需编排每个模型或工具步骤，仍可在处理期间补充消息。

| 模块 | 负责什么 | 依赖 |
| --- | --- | --- |
| contracts.py | Model、Summarizer、决定、工具、限制与观察数据的公共契约 | 标准库 |
| errors.py | 模型适配器与运行过程共同理解的错误类别 | 标准库 |
| context.py | 连续历史、字节预算、完整消息分片与前缀压缩 | errors |
| runtime.py | 接收与去重、运行状态、效果提交、恢复、订阅和生命周期 | contracts、context、errors |
| chat.py | 可选的兼容 HTTP 适配、协议提示、响应解析与模型摘要 | contracts、errors；请求时才导入 httpx |
| tools.py | 显式引入的本地终端、文件和检索工具 | contracts |
| __init__.py | 稳定的公共导入入口 | contracts、context、errors、runtime |

模型适配器与常用工具不导入运行实现。业务角色、配置发现、输入编辑和展示属于宿主应用；库不读取本机配置，不自动注册工具。默认协议为英文，宿主文本保持原样。

每份 conversation 保存连续记忆，同一时刻最多一个活跃 run；一个 run 可以接收多条消息并产生多次输出。每个 run 的 asyncio.Queue 串行消费消息、更新状态，模型、工具、摘要和退避等待在队列外执行，结果回队后提交。不同会话与多个工具可以并发。

```text
submit → 接收凭据、消息入队 → 消费并更新状态
                                  ↓
                          捕获快照，发起慢操作
                                  ↓
                 结果回队 → 校验并提交决定 → 输出 / 工具 / 等待 / 终态

query ← 快照       subscribe ← 事件       wait ← 终态信号
```

输入接收即分配版本，模型结果提交前比较版本，过时决定不能发答案或启动工具。排队输入全部消费后统一准备下一次判断。pending 表示全部在途工具，waiting_for 仅表示下一步必须等的结果；普通调用默认等本批，模型可按次指定例外。等待不阻止接收、查询与取消，也没有无新消息时的推理空转。

输出与终态分开：有 pending 时可以先输出再继续；没有 pending 且模型仅回答时结束。观察订阅与终态等待独立，慢订阅者不会影响处理。运行记录与会话记忆分别通过 prune 和 forget 释放。

上下文超出字节预算时，旧前缀按完整消息分片摘要，仅单条过长记录拆片；在预算内保留短用户原文。摘要全部成功后原子替换旧前缀，压缩期间的新消息保留。模型常见故障内部有界恢复；工具错误作为事实回流，不盲目重试副作用。

实现保持普通状态字段、集合和分支，状态推进集中在 runtime 中，未增加 broker、状态机框架或任务树。当前边界与准确字段见 [接口说明](api.md)；快速运行与开发检查见 [README](../README.md)。
